## 已确认的用途

同事输入节日主题和所需元素，在统一的公司美术风格内完成设计。入口按钮与全屏展示属于同一套节日设计的两种配套输出。

共同风格见 [美术风格与配套输出原则](docs/art-style.md)，执行入口见 [中文提示词技能](skills/festivals-prompts/SKILL.md)。技能随插件一起分发，不依赖 handraw-style、图片资源或额外运行环境。

## 使用方式

1. 输入节日主题与元素要求，直接获得完整的中文全屏展示提示词。尺寸、文案和布局要求可按需附加；没有给出的可选规格不作为必填项。
2. 在自己的生图工具中完成大图。
3. 提供本次成图或对其实际元素与外观的文字描述，获得继承大图视觉设计的中文入口按钮提示词。
4. 可以直接编辑提示词，或要求只修改其中某项；后续以用户最新确认版本为准。

插件不会根据节日名称套用固定元素。用户可自行给出元素，也可明确授权自由设计；仅有节日名时会询问内容要求。插件不附英文译文，也不会在请求提示词时启动生图流程。

固定的是美术造型、材质与渲染语言，氛围由用户输入决定。详细输入以整理去重为主，简略输入才补足必要设计；风格段保持简短，不重复堆叠形容词。只有会显著改变画面的未解决冲突才提出简短选择问题，不把氛围差异当作风格失效。

## 安装与分发路线

参考项目：`D:\Projects\Codex\Codex Rtk\codex-rtk`。

采用相同的 Codex 原生插件市场路线：

1. 为同事的 GitHub 账号授予私有仓库访问权限，并确保其本机 Git 凭据可读取该仓库。

仅参考 RTK 的插件清单与市场分发结构；当前不需要其 Hook、命令压缩、后台服务或 Node.js 运行依赖。

## 版本维护

使用“版本号工具”的默认兼容计算模式。先提交功能，再根据已提交的 Git 历史同步版本：`.codex-plugin/plugin.json` 使用语义版本加构建号，`version.json` 保存工具原始计算结果及源码提交。随后单独提交版本元数据。工具本身作为维护工具使用，不打包进此插件。
